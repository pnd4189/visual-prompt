## What Happened

Shipped v0.3 of visual-prompt skill with a **selectable 18-style art system** for Chinese web-novel visuals. Key change: **genre and style are now fully decoupled** — any style works for any genre (soft recommendation only).

## The Brutal Truth

This was satisfying to lock in because the design worked exactly as planned. Four linear phases, no surprises, no mid-execution design flips. Verification was strict (18 IDs consistent across 3 files, no residual hardcoded refs to Hero/Crouching Tiger outside the painterly entry, cache key properly threaded). The tricky bit was **not** the code—it was the decisions: should negative budget be 24 or keep 20? (Chose 24: 10 anti-Western + 5 genre + 5 AI + 4 style.) Should style be coupled to genre via hard rules or soft recommend? (Soft won—genre/style picker are separate, user choice overrides both.) Those locked in cleanly and didn't waver.

## What We Tried

One decision swing during validation: should music score refs be decoupled? **Initial:** leave music refs to music-mood-mapping.md (hardcoded Crouching Tiger). **Then:** Q4 validation question: "how does a video-oriented style with K-pop synth get mapped to strings?" Answer: it can't under hardcode. **Fix:** added `music/score anchor` field to style catalog; music-prompt-builder + music-mood-mapping now read from `.work/active-style.md`. No code churn—just a schema field + 2 reads. Locked in Phase 1; propagated to Phases 2, 3, 4.

## Root Cause Analysis

Why this worked so cleanly:
1. **Brainstorm locked decisions upfront** — all 4 design questions (style interactivity, genre/style coupling, negative cap, music decouple) answered and validated before Phase 1 kicked off.
2. **Linear dependency chain (P1→P2→P3→P4)** — Phase 1 defines schema; Phase 2 materializes it; Phase 3 consumes it; Phase 4 documents. Zero backtracking.
3. **Web research decoupled from code** — catalog is a pure Markdown reference; no code dependency until prompts read it. Easy to verify, easy to update.
4. **Materialize + hash pattern** — stealing the cache-key paradigm from v0.2's qa/bible/plan hash gave us invalidation for free. No special cache-bust logic needed.

## Lessons Learned

- **Lock decisions with explicit questions, not vague intent.** "Genre/style decoupling?" → Q1/Q2/Q3/Q4 + rationale → no mid-build surprises.
- **Schema first, code second.** Define the `active-style.md` format and verify it can express all 18 styles before writing a single prompt.
- **Threading pattern pays off.** Materialize intermediate state (`.work/active-style.md`) once; let all downstream prompts read it. Beats passing style ID through 5 function layers.
- **Soft recommend beats hard rule.** "Best genres for this style" is advisory; user can override. Gives freedom without fragility.
